# 資料、檔案及部署交接方案

## 1. 資料庫內容

目前資料庫主要有兩張業務表：`users` 保存學校及管理員帳戶，`esgSubmissions` 保存年度 ESG 提交。提交表包含學校名稱、報告年度、共用基本資料、E／S／G JSON、狀態、提交時間、管理員回覆摘要及報告檔案資訊。

| 表 | 主要用途 | 重要關聯 |
|---|---|---|
| `users` | 學校及平台管理員帳戶 | `role` 為 `user` 或 `admin` |
| `esgSubmissions` | 年度草稿、正式提交及回覆 | `ownerId` 指向帳戶；同一帳戶及報告年度有唯一限制 |

學校帳戶密碼不是以明文保存，而是以 scrypt 雜湊保存。不要將帳戶密碼由資料庫匯出到一般文件；資料庫備份本身應加密，並透過獨立安全渠道交付。

## 2. 資料庫移轉步驟

若維持同一個資料庫服務，應先建立加密備份，於測試資料庫還原，執行應用程式測試，再安排短暫維護窗口切換。若搬到新資料庫，應先確認資料庫版本及時區，再還原 schema 和資料，確認 `users`、`esgSubmissions` 的筆數、外鍵語意、唯一限制和日期欄位。

新的維護者應在目標環境執行下列非破壞性驗證：確認可以連線、讀取 schema、建立測試學校帳戶、保存草稿、正式提交及由管理員查看。測試完成後要刪除測試帳戶和測試提交，不應把測試資料當成正式學校資料。

```bash
pnpm check
pnpm test
pnpm build
```

`drizzle/schema.ts` 是目前資料模型的程式來源，`drizzle/*.sql` 是 migration 記錄。任何 schema 修改都應先在測試資料庫驗證，再按正式 migration 流程執行；不要用 `DROP TABLE` 或未審核的破壞性 SQL 取代移轉。

## 3. 帳戶及權限交接

學校帳戶使用自設電郵及密碼。平台管理員權限由 `users.role = 'admin'` 控制。交接時應至少建立一個新的機構管理員帳戶，確認可以登入 `/admin`、查看提交、標記審閱、撰寫回覆及管理報告連結，再停用或刪除舊維護者帳戶。管理員密碼不應放入交接文件。

如果要保留現有學校帳戶和提交歷史，資料庫必須跟隨移轉；如果只是把程式碼交給另一家公司而不移轉資料，對方只能取得程式碼，不能查看現有學校資料。資料擁有權、保留期限、刪除要求及備份保留政策，應由機構以書面確認。

## 4. 檔案儲存交接

管理員回覆報告使用 storage helper 上載，資料庫只保存檔案名稱及 URL／key。檔案本體不在 Git repository，也不在 ZIP。交接時要列出現有檔案的 key、用途、所屬提交及存取權限，並在新 storage 環境以測試帳戶確認上載及下載。

如果維持 Manus storage，必須處理原專案 storage 的所有權和存取權。如果完全搬離 Manus，應先批量下載並加密保存原始檔案，再上載至新 S3-compatible storage，然後更新 `reportFileUrl` 或建立可追蹤的 key mapping。不要只把舊 `/manus-storage/...` URL 當作永久備份。

## 5. 方案 A：繼續使用 Manus 部署

此方案保留目前的 Manus WebDev hosting、資料庫及 storage。下一手需要獲得該專案的正式維護權限，或由機構帳戶建立可管理的專案權限；不應共用原持有人的登入資料。現有網站域名為 `schoolesg-4eqa8bqr.manus.space`，正式交接前應確認域名、專案、Secrets、資料庫及 storage 的擁有權均屬機構。

優點是改動較少，現有部署設定和 storage 整合可繼續使用。限制是下一手仍需依賴 Manus 的專案和服務，不能只靠 GitHub repository 獨立重建全部執行環境。

## 6. 方案 B：完全搬離 Manus

此方案把程式碼匯出到機構控制的 GitHub，配置自己的 Node.js hosting、MySQL／TiDB、S3-compatible storage、域名及 Secrets 管理。需要重新設定環境變數、資料庫連線、檔案儲存 proxy、通知服務、分析服務及任何 Manus 專用 runtime 行為。

搬遷完成前應先在 staging domain 做完整驗收。確認學校註冊、登入、草稿、正式提交、管理員審閱、報告上載、報告下載和錯誤記錄全部正常，才切換正式 DNS。切換後要保留舊環境一段已由機構批准的觀察期，再決定是否停止舊服務。

## 7. 正式切換清單

| 階段 | 驗收內容 |
|---|---|
| 程式碼 | 新維護者可 clone、安裝、check、test、build |
| 資料庫 | schema、帳戶、提交、狀態及日期欄位已核對 |
| 儲存 | 報告檔案可上載、下載及按權限存取 |
| 權限 | 新管理員可工作；舊權限已撤銷或降級 |
| Secrets | 全部由新環境注入，沒有真值進入 Git 或 ZIP |
| 網域 | DNS、HTTPS、登入 cookie 及回調設定已確認 |
| 營運 | 備份、錯誤記錄、監控及事故聯絡人已定義 |
